## GitHub concepts used in this assignment
- **Issue**: defines the goal and acceptance criteria for the work before any content is written.
- **Branch**: an isolated line of work (feature/github-ai-workflow) so the default branch stays stable until the work is reviewed.
- **Commit**: a focused, meaningful snapshot of one logical change, with a clear message explaining what and why.
- **Pull request**: a proposal to merge the feature branch into the default branch, including a summary, links, and a checklist for review.
- **Default branch (main)**: the stable, canonical branch that reflects the project's accepted state.

## How these connect
The issue defined the goal and acceptance criteria before any work began.
The feature branch kept that work isolated from main so main stayed
stable during development. Each commit represented one focused change
tied back to the issue's checklist - README clarity, workflow
documentation, and the AI-use record. The pull request proposed merging
that branch into main, summarized the changes, linked back to the issue
with "Closes #1," and included a self-review comment identifying a
strength and an improvement before the improvement was actually made in
a follow-up commit. Once addressed, the pull request was merged into
main, completing the full workflow loop from issue to merged, documented
change.
